# OGM — Управление главного механика

Локальная система учёта. Первый этап: сотрудники, автомобили, топливные карты.

## Запуск Windows
Установите Python 3.11+ и Node.js (только для первой сборки), запустите START.bat. При первой сборке требуется интернет для установки TypeScript. После сборки Node.js и интернет не требуются. База создаётся в data/ogm.sqlite3, сервер слушает только 127.0.0.1. Закройте окно сервера для остановки.

Ручной запуск: npm install, npm run build, python server.py.
Тесты: python -m unittest discover -s tests

Справочники связаны через идентификаторы сотрудников. На первом этапе один сотрудник может иметь один закреплённый автомобиль и одну карту; при смене закрепления конфликт необходимо снять явно. Архивация сотрудника освобождает его автомобиль и карту; архивные записи можно восстановить. Даты страхования необязательны, нормы — л/100 км. Предупреждение в интерфейсе за 30 дней.

Остальные разделы обозначены как запланированные; ИИ и Cloud.ru пока не подключены.
Не публикуйте папку data/ и реальные данные сотрудников в GitHub. Для резервной копии остановите сервер и скопируйте data/.

## ГСМ (0.2)
Загрузите XLS/XLSX в разделе ГСМ. Поддерживаются блоки «Карта №», строки «Отгрузка» и «Возврат» (Операция, Дата, Время, Азс, Топливо, Цена, Кол-во, Сумма), не произвольные форматы. Исходники хранятся только в локальной SQLite, лимит 12 МБ. Новые карты создаются без закрепления. Суммы и литры — в сотых, возвраты отрицательные. Повторные файлы отсеиваются по SHA-256, одинаковые операции — по полному набору полей и порядковому номеру среди одинаковых строк; без идентификатора поставщика совпадающие операции в разных выгрузках могут быть неразличимы. История начинается с установки 0.2: для старых операций задайте реальные даты, сотрудника и автомобиль в разделе «История закреплений». Ручные периоды имеют приоритет; пересечения ручных периодов запрещены. Тип топлива автомобиля — бензин, дизель или не указан. Отчёты выявляют отсутствие закрепления и несоответствие топлива; сверки с путевыми листами и нормами пока нет. Экспорт охватывает выбранный месяц независимо от поиска. Для Excel нужны xlrd и openpyxl: START.bat установит их при отсутствии (интернет при первом запуске). При обновлении выполните npm run build. CI дополнительно использует xlwt только для синтетических XLS-тестов.

## Списание ГСМ (0.3)
Выберите месяц в разделе «Списание ГСМ». Заполните первый/последний путевой лист, показания одометра, остатки, вместимость бака и сезон. Если начальный остаток пуст, используется конечный остаток сохранённой карточки прошлого месяца. Пробег = конечный − начальный одометр; ручной пробег требует причины. Нормы копируются из автомобиля при сохранении карточки; режим сезона выбирается вручную (лето, зима или раздельный пробег). Заправки по картам берутся из ГСМ с исторической привязкой на дату; неподходящее/неизвестное топливо и операции без автомобиля не включаются и отмечаются. Сторонние приходы и сливы вводятся вручную, неподтверждённые учитываются только в предварительном расчёте с предупреждением. Расход факт = остаток начальный + заправки по картам + сторонний приход − слив/передача − конечный остаток. Отрицательные результаты не исправляются автоматически. Все сохранения требуют основания, история содержит до/после. Экспорт XLSX с печатной областью и пустыми полями согласования; лист ручных операций. Старые XLSX по образцу октябрьской ведомости (заголовки строки 7–8, строки данных с 9) сохраняются отдельно вместе с оригиналом и сопоставляются по госномеру. Можно перенести пробег/остатки в текущую карточку после проверки; заправки и фактический расход из старой таблицы не добавляются к операциям автоматически. В образце две группы конечного остатка: в новом отчёте вторая заменена на «Слив / передача», в архиве исходные группы сохранены. Все расчёты предварительные; закрытие периода, полная база путевых листов, авторизация и юридическое утверждение не реализованы. Запуск START.bat пересоберёт интерфейс при отсутствии writeoff-ui.js. Данные исходных файлов не публикуются.

## OGM 0.4 — операционный контур
Путевые листы: отдельный реестр, редактирование и архив; в карточке списания кнопка предлагает первый/последний лист, остатки и одометр, не заменяя непустые поля. Настройки сезонных дат (ММ-ДД) задаются по приказу; переходный месяц рассчитывается только при согласованном пробеге листов. История водителей, норм, статусов начинается с миграции 0.4, старые периоды не угадываются. Подразделение в карточке сотрудника. Аналитика: месяцы, автомобили, годовые суммы, перерасход, недостающие данные текущего месяца, даты страховок, АЗС, цены и признаки подозрительных операций. Суббота/воскресенье — только сигнал, не рабочий календарь; 3 покупки за день или 200 л — ориентиры для проверки, а не обвинения. История автомобиля включает доступные путевые листы, балансы, операции и исходные ведомости; история карты — закрепления и операции. Журнал триггеров SQLite показывает последние 500 изменений; импорт топлива журналируется по файлам, операции остаются в реестре. Проверка базы и потенциальных дубликатов не исправляет их автоматически.
Резервное копирование: автоматически при запуске и ежедневно при работающем сервере, вручную в настройках. Копии проверяются и сохраняются в data/backups; храните отдельную копию вне носителя. Восстановление только после остановки OGM: RESTORE.bat перечисляет файлы; RESTORE.bat ИМЯ.sqlite3 запускает подтверждение. Создаётся предвосстановительная копия. Блокировка предотвращает параллельный запуск OGM/восстановление. BAT поддерживает относительные пути, существующий Python/Node и опциональные runtime/python/python.exe и runtime/node/npm.cmd (дистрибутивы не включены). Первый запуск/обновление может требовать установки зависимостей и сборки. Рабочие данные не включены в GitHub. Физический USB/SSD и запуск BAT необходимо проверить на рабочем ПК.

## OGM 0.5 — автоматизация ГСМ
В ГСМ загрузка XLS/XLSX сначала показывает структурную проверку формата, месяцы операций, распознанные марки топлива, новые карты, повторы и связи на дату операций. Запись происходит после подтверждения. Новые карты не закрепляются автоматически, неизвестные виды топлива не угадываются; исторические ключи дедупликации сохранены. Поддерживаются известные шаблоны, не произвольные Excel. В этом этапе не реализована сверка с итогом поставщика (пункт 7 не выбран). Кнопки «Проверка заправок» и «Прогноз и цены» используют локальные вычисления. Цена — средневзвешенная цена покупок за выбранный и предыдущий месяц, возвраты исключены. Прогноз — среднее фактического расхода по активным автомобилям за 2–3 пригодных предыдущих завершённых месяца, с покрытием и диапазоном наблюдений; без сезонной поправки, не является заказом или гарантией. Недостаток данных не заменяется нулём. Исторический вид топлива до появления истории требует ручной проверки. В списании используются существующие переносы остатков и расчёты Python. «Предложить пробег» суммирует пробеги доступных путевых листов, показывает исходные показания и разрывы; неполные/обратные или неоднозначные показания не заменяются догадкой. Применение только в черновик с подтверждением и сохранением основания. «Проверить готовность» разделяет блокирующие замечания и предупреждения; Excel для бухгалтерии содержит лист проверки и явную маркировку черновика при блокировках. Не является официальным утверждением списания. Cloud.ru не подключён, интернет и новые платные вызовы для этих функций не нужны. BAT проверяет отпечаток исходников фронтенда и пересобирает только при изменении или отсутствии JS (для сборки нужен Node). Тесты синтетические, реальный импорт и запуск BAT требуют проверки.

## OGM 0.6 — исправления аудита (первая часть)
При сохранении месячной карточки сохраняются параметры автомобиля (госномер, модель, вид топлива, водитель) и начальный остаток. Старые карточки без снимка помечаются для ручной сверки; при пересохранении оператор должен подтвердить параметры, исторические значения автоматически не восстанавливаются. Вид топлива в сохранённом снимке не заменяется текущим справочником. Сверка заправок требует явного подтверждения и основания (включая отсутствие заправок); контрольная сумма отслеживает изменения операций. Закрытие месяца только после проверки готовности, с основанием; отчёт хранится как неизменяемый снимок. Открытие снова требует причины; предыдущие снимки остаются в SQLite. Новые операции и периоды карт, изменения путевых листов и импорт старого отчёта в закрытый месяц блокируются. Запрещено предлагать пробег по пересекающимся одометрам; готовность требует наличия первого и последнего листа. Возможные совпадения ручных и карточных заправок отмечаются, не удаляются. Закрытие — внутренний контроль, не юридическое утверждение. Порт 8765 с резервным случайным портом; 30 ежедневных резервных копий, ручные не удаляются, технический лог в data/ogm.log. Интерфейс: реальные данные главной, SVG график, компактность, закреплённые заголовки и первый столбец, сортировка и выбор столбцов (на текущий сеанс). Пока не реализованы универсальный импорт и отмена импорта, редактор исторических периодов, независимый источник пробега, полноценная версия миграций, внешняя копия, постраничная загрузка, браузерные E2E, отдельные настройки таблиц, полный журнал изменений и оставшиеся пункты аудита. Проверка реальных данных и визуальная проверка обязательны.

Дополнение: отмена последнего действующего импорта сохраняет исходный файл и удалённые операции в журнале fuel_corrections; отмена более раннего импорта запрещена, чтобы не потерять операции перекрывающихся ведомостей. Повторная загрузка отменённого оригинала восстанавливает его операции после обычной проверки. Ручные исторические периоды можно исправить или удалить с обязательным основанием; закрытые месяцы защищены. Видимость столбцов сохраняется по таблицам в браузере при стабильном порте. Это заменяет соответствующие ограничения первого этапа; произвольная отмена старых импортов, редактирование отдельных операций и полноценный браузерный аудит остаются отдельными задачами.

## OGM 0.7 — продолжение аудита
Известные заголовки топливных ведомостей теперь распознаются независимо от порядка столбцов; неизвестная строка, похожая на операцию, блокирует импорт вместо молчаливого пропуска. Нестандартные шаблоны могут потребовать отдельной настройки. В настройках доступна выгрузка проверенной SQLite-копии на выбранный пользователем носитель; при остановленном OGM можно выполнить `python maintenance.py backup-to "D:\\OGM-backup"` (папка должна существовать). Передача в облако отсутствует. Журнал показывает различия по полям, диагностика — версию схемы и последнюю копию. Таблицы отображаются страницами по 100 строк с сортировкой полного набора, но API ещё загружает весь набор в память. Добавлены тесты HTTP Host/Origin, API, безопасной выгрузки копий и переставленных колонок. Реальные XLS и запуск BAT/браузер на рабочем компьютере остаются непроверенными; исправление произвольных повреждённых книг, универсальный импорт, серверная пагинация, отдельные операции и прочие незакрытые пункты требуют дальнейшей реализации.

## Запуск: исправление сломанного Python Launcher
START.bat и RESTORE.bat используют FIND_PYTHON.bat. Проверяется фактический запуск Python и SQLite, а не только наличие py.exe. Приоритет: переносимый полноценный runtime, рабочие версии 3.13/3.12/3.11/3.14 через py, затем установленные python.exe и PATH без стандартного псевдонима Microsoft Store. `START.bat --check-python` проверяет выбор интерпретатора; `START.bat --check` также проверяет зависимости и сборку без запуска сервера. Если ни одного рабочего Python 3.11+ нет, установите Python 3.13. База data/ не изменяется в режиме проверки. Node.js нужен только для сборки. При обновлении сохраните папку data/ и замените файлы запуска вместе.

### Старые русские XLS
Для старых книг BIFF до версии 8 без записи CODEPAGE импорт использует Windows-1251 вместо стандартного Latin-1, чтобы корректно читать карту, операцию, АЗС и топливо. Явно заданные кодировки и Unicode XLS/XLSX сохраняются. Проверка неизвестных операций остаётся включённой. Добавлен синтетический тест старого BIFF5 без CODEPAGE; рабочая ведомость не публикуется. Для XLS без указанной кодировки из других языковых регионов может потребоваться отдельная настройка.

## Упрощённое ежемесячное списание
Откройте «Списание ГСМ», выберите месяц, автомобиль и «Внести данные». Введите начальный остаток, начальный и конечный одометр, конечный остаток. Заправки по картам берутся из выписки за даты выбранного месяца с вычетом возвратов. Если прошлые операции ещё не связаны с автомобилем, выберите карту и подтвердите её использование этим автомобилем весь месяц; при конфликте или смене карты/водителя в середине месяца используйте исторические периоды. Нормы подтягиваются из справочника (сохранённые нормы сохраняются), сезон — из настроек либо ручного выбора. Расход факт = начало + карточные и ручные приходы − слив − конец; без конечного остатка факт не вычисляется. Номера путевых листов необязательны в режиме месячных показаний, но могут быть внесены отдельно; сверка топлива и блокировки закрытого месяца сохранены. Сторонние заправки и исправленный пробег в дополнительных полях. Выбор карты не заменяет действующие связи молча. Старые закрытые отчёты не пересчитываются. Применяются существующие правила проверки и экспорта XLSX. Новых зависимостей нет.

### Видимость заправок по карте
В ГСМ режим «По картам» показывает объёмы бензина, дизеля и остальных продуктов за выбранный период независимо от закрепления автомобиля. В списании показаны доступные месяцы выписок, текущая карта водителя, её фактические итоги выписки и статус исторической связи. Кнопка «Подтвердить за месяц» создаёт проверенную историческую привязку с журналом; уже внесённые одометры и остатки не переписываются. При смене карты или автомобиля внутри месяца используются отдельные исторические периоды. В месячном режиме факт не отображается при ожидающей подтверждения связи текущей карты или отсутствии операций без подтверждения отсутствия заправок. Закрытые снимки не меняются.

### Рабочая панель месяцев списания
В «Списание ГСМ» сверху 12 месяцев выбранного года. Зелёный означает наличие операций в загруженных выписках за даты этого месяца, красный — отсутствие операций. Синяя рамка выделяет выбранный отчётный период. Жёлтый текст отдельно показывает замечания; наличие выписки не означает её полноту или готовность списания. Пустые выписки без операций прежний импорт не принимает, а отсутствие заправок можно подтвердить в карточке. Переключение года и месяца не меняет данные. Кнопка «Загрузить выписку ГСМ» показывает даты периодов перед импортом; выбранный отчётный месяц остаётся прежним. Статусы вычисляются из SQLite (отменённые операции не учитываются); закрытые отчёты остаются снимками. Готовность и закрытие по прежним проверкам. Итоги над таблицей относятся ко всему месяцу независимо от поиска, отклонение только по автомобилям с обоими показателями. Экспорт и старые отчёты доступны в меню «Отчёты и архив». Новых зависимостей нет.

### Компактное списание ГСМ
Лента месяцев с зелёной/красной точкой (наличие операций), тонкие разделители, три ключевых итога. В таблице можно менять начальный/конечный остаток, показания одометра и сезон, Enter переводит фокус на следующее поле. Начальный остаток и начальный одометр предлагаются из прошлого месяца, если поле ещё не заполнено, включая незакрытый предыдущий месяц; оператор проверяет их перед сохранением. Предложения сохраняются вместе с редактируемой строкой. Мгновенный расчёт в браузере предварительный, окончательный — Python после сохранения. Кнопка «Сохранить» записывает все изменённые строки одной транзакцией (до 500), с проверкой ревизий, закрытия месяца и допустимых полей; при ошибке откатываются все записи. Черновики в памяти вкладки; переходы, экспорт и закрытие при несохранённых изменениях блокируются, при выходе браузер предупреждает. Сторонние операции, ручная сверка, исправленный пробег и прочие расширенные данные доступны через ⋯. Существующие данные и снимки не мигрируют. Таблица с фиксированными заголовком и первым столбцом прокручивается горизонтально; автоматизация и финальная проверка остались локальными. Браузерный предварительный расчёт может отличаться на округлении или при автоматическом выборе переходного сезона, итог сервера имеет приоритет. Визуальная проверка на реальном экране обязательна.

### Рабочее пространство расчёта по автомобилю
В списании по умолчанию открывается режим «По авто»: слева список с поиском и фильтрами (все, требуют проверки, изменённые), справа четыре основных показания, сезонная норма, заправки по картам, топливный баланс и сравнение факта с нормой. Стрелки переключают автомобили, Enter переводит фокус между полями. Режим «Таблица» остаётся для массового ввода; выбор режима запоминается локально. Оба представления используют одни и те же черновики и одну кнопку атомарного сохранения. Для подтверждения закрепления карты, сверки выписки и расширенного редактирования сначала сохраните или отмените черновик. Литры по неподтверждённой карте показываются отдельно и не включаются автоматически в баланс. Предварительные значения и замечания к сохранённым данным подписаны отдельно. При закрытом месяце ввод отключён. Для маленьких экранов список автомобилей располагается над расчётом. Автоматические тесты серверной логики и сборка проверяют совместимость; визуальный и интерактивный браузерный тест на рабочем ПК остаётся необходимым.

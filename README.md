# OGM — Управление главного механика

Локальная система учёта. Первый этап: сотрудники, автомобили, топливные карты.

## Запуск Windows
Установите Python 3.11+ и Node.js (только для первой сборки), запустите START.bat. При первой сборке требуется интернет для установки TypeScript. После сборки Node.js и интернет не требуются. База создаётся в data/ogm.sqlite3, сервер слушает только 127.0.0.1. Закройте окно сервера для остановки.

Ручной запуск: npm install, npm run build, python server.py.
Тесты: python -m unittest discover -s tests

Справочники связаны через идентификаторы сотрудников. На первом этапе один сотрудник может иметь один закреплённый автомобиль и одну карту; при смене закрепления конфликт необходимо снять явно. Архивация сотрудника освобождает его автомобиль и карту; архивные записи можно восстановить. Даты страхования необязательны, нормы — л/100 км. Предупреждение в интерфейсе за 30 дней.

Остальные разделы обозначены как запланированные; ИИ и Cloud.ru пока не подключены.
Не публикуйте папку data/ и реальные данные сотрудников в GitHub. Для резервной копии остановите сервер и скопируйте data/.

## ГСМ (0.2)
Загрузите XLS/XLSX в разделе ГСМ. Поддерживаются блоки «Карта №», строки «Отгрузка» и «Возврат» (Операция, Дата, Время, Азс, Топливо, Цена, Кол-во, Сумма), не произвольные форматы. Исходники хранятся только в локальной SQLite, лимит 12 МБ. Новые карты создаются без закрепления. Суммы и литры — в сотых, возвраты отрицательные. Повторные файлы отсеиваются по SHA-256, одинаковые операции — по полному набору полей и порядковому номеру среди одинаковых строк; без идентификатора поставщика совпадающие операции в разных выгрузках могут быть неразличимы. История начинается с установки 0.2: для старых операций задайте реальные даты, сотрудника и автомобиль в разделе «История закреплений». Ручные периоды имеют приоритет; пересечения ручных периодов запрещены. Тип топлива автомобиля — бензин, дизель или не указан. Отчёты выявляют отсутствие закрепления и несоответствие топлива; сверки с путевыми листами и нормами пока нет. Экспорт охватывает выбранный месяц независимо от поиска. Для Excel нужны xlrd и openpyxl: START.bat установит их при отсутствии (интернет при первом запуске). При обновлении выполните npm run build. CI дополнительно использует xlwt только для синтетических XLS-тестов.

## Списание ГСМ (0.3)
Выберите месяц в разделе «Списание ГСМ». Заполните первый/последний путевой лист, показания одометра, остатки, вместимость бака и сезон. Если начальный остаток пуст, используется конечный остаток сохранённой карточки прошлого месяца. Пробег = конечный − начальный одометр; ручной пробег требует причины. Нормы копируются из автомобиля при сохранении карточки; режим сезона выбирается вручную (лето, зима или раздельный пробег). Заправки по картам берутся из ГСМ с исторической привязкой на дату; неподходящее/неизвестное топливо и операции без автомобиля не включаются и отмечаются. Сторонние приходы и сливы вводятся вручную, неподтверждённые учитываются только в предварительном расчёте с предупреждением. Расход факт = остаток начальный + заправки по картам + сторонний приход − слив/передача − конечный остаток. Отрицательные результаты не исправляются автоматически. Все сохранения требуют основания, история содержит до/после. Экспорт XLSX с печатной областью и пустыми полями согласования; лист ручных операций. Старые XLSX по образцу октябрьской ведомости (заголовки строки 7–8, строки данных с 9) сохраняются отдельно вместе с оригиналом и сопоставляются по госномеру. Можно перенести пробег/остатки в текущую карточку после проверки; заправки и фактический расход из старой таблицы не добавляются к операциям автоматически. В образце две группы конечного остатка: в новом отчёте вторая заменена на «Слив / передача», в архиве исходные группы сохранены. Все расчёты предварительные; закрытие периода, полная база путевых листов, авторизация и юридическое утверждение не реализованы. Запуск START.bat пересоберёт интерфейс при отсутствии writeoff-ui.js. Данные исходных файлов не публикуются.

## OGM 0.4 — операционный контур
Путевые листы: отдельный реестр, редактирование и архив; в карточке списания кнопка предлагает первый/последний лист, остатки и одометр, не заменяя непустые поля. Настройки сезонных дат (ММ-ДД) задаются по приказу; переходный месяц рассчитывается только при согласованном пробеге листов. История водителей, норм, статусов начинается с миграции 0.4, старые периоды не угадываются. Подразделение в карточке сотрудника. Аналитика: месяцы, автомобили, годовые суммы, перерасход, недостающие данные текущего месяца, даты страховок, АЗС, цены и признаки подозрительных операций. Суббота/воскресенье — только сигнал, не рабочий календарь; 3 покупки за день или 200 л — ориентиры для проверки, а не обвинения. История автомобиля включает доступные путевые листы, балансы, операции и исходные ведомости; история карты — закрепления и операции. Журнал триггеров SQLite показывает последние 500 изменений; импорт топлива журналируется по файлам, операции остаются в реестре. Проверка базы и потенциальных дубликатов не исправляет их автоматически.
Резервное копирование: автоматически при запуске и ежедневно при работающем сервере, вручную в настройках. Копии проверяются и сохраняются в data/backups; храните отдельную копию вне носителя. Восстановление только после остановки OGM: RESTORE.bat перечисляет файлы; RESTORE.bat ИМЯ.sqlite3 запускает подтверждение. Создаётся предвосстановительная копия. Блокировка предотвращает параллельный запуск OGM/восстановление. BAT поддерживает относительные пути, существующий Python/Node и опциональные runtime/python/python.exe и runtime/node/npm.cmd (дистрибутивы не включены). Первый запуск/обновление может требовать установки зависимостей и сборки. Рабочие данные не включены в GitHub. Физический USB/SSD и запуск BAT необходимо проверить на рабочем ПК.
